# PRD — void

- 상태: Draft v0.1
- 작성일: 2026-10-27

## 1. 문제

회의 녹음 앱은 많지만 대부분 (a) 시작까지 단계가 많고, (b) 음성을 클라우드로 보내며, (c) 결과물이 앱 안에 갇혀 있다.
민감한 회의(인사, 투자, 고객 정보)일수록 녹음 자체를 포기하게 된다.

## 2. 타깃 사용자

- 회의가 잦고, 회의록을 Notion/Slack/자체 시스템으로 옮겨야 하는 사람
- 보안 정책상 클라우드 STT/LLM을 쓸 수 없는 조직의 구성원
- 자동화(Zapier, n8n, Make, 사내 봇)를 이미 쓰고 있는 사람 → webhook이 곧 연동 수단

## 3. 목표 / 비목표

**목표**
- 앱을 열지 않고 1탭으로 녹음 시작
- 종료 후 N분 내에 요약·액션아이템이 webhook으로 도착
- 네트워크를 끊어도 녹음·전사·요약이 모두 동작

**비목표 (v1)**
- 실시간 협업 편집, 팀 공유 공간
- 클라우드 동기화 / 계정 시스템
- 화자 이름 자동 식별 (화자 *구분*은 v2 후보)
- 화상회의 앱 연동 봇

## 5. Webhook 페이로드 (초안)

```json
{
  "version": "1",
  "id": "mtg_01J...",
  "started_at": "2026-10-27T10:00:00+09:00",
  "ended_at": "2026-10-27T10:42:13+09:00",
  "end_reason": "silence_timeout | manual",
  "language": "ko",
  "title": "Q4 로드맵 리뷰",
  "summary": "…",
  "decisions": ["…"],
  "action_items": [{ "task": "…", "owner": "…", "due": null }],
  "transcript": [{ "start": 0.0, "end": 4.2, "text": "…" }]
}
```

- 서명 (비밀키 설정 시): 수신 측 위조·재전송 검증용
  - `X-Void-Timestamp: <unix 초>`
  - `X-Void-Signature: sha256=<hex HMAC-SHA256(secret, "<timestamp>.<body>")>` — 본문 앞에 타임스탬프와 `.`을 붙여 서명
  - 수신 측은 같은 방식으로 계산해 상수 시간 비교하고, 타임스탬프가 5분 이상 지난 요청은 버린다
- `Idempotency-Key: <meeting id>` — 재시도로 같은 회의가 두 번 와도 수신 측에서 중복 제거
- 값이 없는 `owner`/`due`는 키를 생략하지 않고 `null`로 보낸다
- transcript 포함 여부는 설정으로 선택 (기본: 포함 안 함 → 유출 표면 최소화)

## 6. 프라이버시 원칙

1. 오디오·전사·요약은 기기 밖으로 나가지 않는다. **유일한 예외는 사용자가 명시적으로 등록한 webhook.**
2. 분석/크래시 리포팅 SDK 미탑재. 네트워크 권한 사용처는 webhook 하나뿐임을 문서로 공개.
3. webhook 미설정 시 앱은 네트워크를 전혀 사용하지 않는다.

## 7. 디자인 원칙

- 팔레트: `#000` ~ `#FFF` 사이 gray 단계만. 강조는 색이 아니라 **shadow(elevation)와 weight**로.
- 녹음 중 상태도 빨간 점 대신 grayscale 애니메이션(파형/호흡)으로 표현.
- 화면은 3개로 제한: 홈(녹음 버튼 + 목록), 회의 상세, 설정.

## 8. 성공 지표

- 시작까지 탭 수: 1
- 60분 회의 → webhook 도착까지: 목표 5분 이내 (기기 기준 측정 필요)
- 무음 자동 종료 오탐률: < 1%
